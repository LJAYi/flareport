# Security policy

Please report vulnerabilities privately to the repository owner rather than opening a public issue. Include the affected adapter or component, impact, reproduction steps, and any evidence that a published update descriptor or generated template was modified.

High-impact examples include archive path traversal, webhook signature bypass, installation-token disclosure, rollout evidence forgery, automatic merge bypass, secret inclusion in generated source, or an adapter that restores unreviewed upstream workflows.

FlarePort adapters package third-party projects. Vulnerabilities in application behavior should normally be reported to the upstream project unless they are introduced by the FlarePort adapter or update path.
